# Учебный маршрут: с чего начать

Этот проект — твоё портфолио. На собеседовании тебя будут спрашивать не «что ты сгенерировал»,
а «почему так» и «что будет, если…». Цель материалов — чтобы ты мог ответить на любой вопрос
по любой строке проекта.

## Правило №1

**Не читай всё подряд.** Каждый день: прочитал раздел → запустил код → сломал → починил → объяснил
вслух (или записал голосовое) за 2 минуты. Если не можешь объяснить — вернись к разделу.

## Порядок чтения кода

1. `app/models.py` — какие есть таблицы и ограничения.
2. `app/schemas.py` — какие данные API принимает и отдаёт.
3. `app/routers/*.py` — какие есть эндпоинты.
4. `app/services.py` — **самый важный файл**: как работает перевод.
5. `tests/conftest.py` — как запускаются тесты.
6. `tests/support/*.py` — вспомогательный код тестов.
7. `tests/api/test_transfers.py` → остальные тесты.
8. `frontend/transfer.html` + `tests/ui/pages.py` + `tests/ui/test_banking_ui.py`.

## Как пользоваться ИИ при обучении (честно)

- Можно: «объясни эту строку», «почему здесь 404, а не 403», «придумай ещё 3 негативных кейса».
- Нельзя (для обучения): просить решить практическое задание целиком. Сначала — своя попытка.
- На собеседовании честно говори: «проект сделан с помощью ИИ-ассистента, я разобрал каждую часть,
  могу объяснить и изменить любой тест». Это нормальная современная практика — если это правда.
